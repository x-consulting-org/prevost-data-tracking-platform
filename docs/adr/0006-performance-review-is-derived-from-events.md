# The performance review is derived from shipment events

The Kollégák screen rates each dispatcher on facts the mailbox and T-Port already deliver: when a request arrived, when the first reply went out (`RESPONSE_SENT`), when a T-Port trip was linked, how often the schedule or details changed, and which vehicle carried each trip. `buildPerformanceReview(dispatchers, shipments, now)` computes every metric and verdict from these on each read, like the alerts (ADR 0003), so there are no stored scores to fall out of step with the timeline. The first reply is an event rather than a column on the shipment, so the timeline stays the one record of what happened.

Dimensions the pilot cannot measure yet (partner relationships, the business quality of a trip choice, escalation, unnecessary internal rounds) are left out rather than estimated: they need email content analysis or a manager's assessment, and a number without data behind it would be worse than none. The thresholds (30-day window, ±15% for "on par", minimum samples) are placeholders until the operations workshop sets them.
